Query a Rust codebase via syntactic (syn) analysis. Finds candidates; you judge them.

AGENT QUICKSTART
  unruster audit --findings-only --top 10  ranked battery, bounded; exit 1 on gating (never pipe it)
  unruster audit --changed-since HEAD~1    same, scoped to your last commit — highest yield
  unruster divergence                sibling paths that disagree — highest yield, start here
  unruster clones                    the same body written out more than once
  unruster near-clones               ...and the copies that have already drifted apart
  unruster concepts                  one concept declared more than once (the noun axis)
  unruster doc-drift                 the docs and the code disagreeing
  unruster vocabulary                `/// unruster: concept(x)` claimed twice, or drifted from
  unruster gate --snippet '<decl>'   BEFORE you write it: what already exists?
  unruster config-drift              same struct built two ways (divergence, for values)
  unruster divergence --handling     one callee, different care (.expect vs .ok())
  unruster contract-drift <fn>       its callers, body withheld; `--reveal` after you judge
  unruster explain <topic>           one repair recipe (cheap); `playbook` for all
  unruster module-uses <mod>         what the rest of the tree takes from a module (removals)
  unruster outline <f>  at <f>:<n>   a file's items with spans; which item owns a line
  unruster show <name>               one item's exact source; bounds itself, never pipe to head
  --json                             every command; named keys (TSV has no header row)

HIGHEST-SIGNAL FIRST
  Divergence beats volume. A check that returns 400 rows returns ~1% real defects;
  two siblings handling the same enum, Result, or index differently is a defect
  far more often than not. Fresh code beats old: `--changed-since` first.
  `error-swallows` and `clones` rank their own rows (score in column 2) and
  `audit` gates on those top tiers only — read them top-down, never by grep.

PRECISION (the `via` column says which tier fired; `explain precision` for the table)
  Rows tagged APPROXIMATE/BEST-EFFORT are leads to verify, not facts. Every run
  reports unparseable macro bodies as blind spots — code in them was NOT analyzed.

GLOBAL FLAGS
  -r/--root <path>       scan root (default `.`); respects .gitignore
  --scope prod|tests|all test-code inclusion (default prod; usage cmds say when it hid tests)
  --changed-since <ref>  rows in files changed vs a git ref (read in --root's repo)
  --format tsv|json      output shape; --json is an alias for --format json
  --context N            print ±N source lines under each row
  --spans                fn labels `name@start-end`; item rows' `at` gains an end
  --summary              drop rows, keep the summary line
  --all-stdout           summaries/notes to stdout too (a --top cut is always there)
  --exclude GLOB         drop matching files (repeatable)
  --cfg KEY[=VALUE]      strip items whose cfg is definitively false
  --fail-on-findings     exit 1 on any finding (0 = clean, 2 = error)
  --no-suppress          ignore waiver comments, report every site
  --suggest-waivers      print the exact waiver comment under each row
  --fingerprints         add the stable `fp` column to TSV (--json always has it)
  --no-cache             skip ~/.unruster_cache (see BEFORE YOU WRITE below)

BEFORE YOU WRITE (`unruster explain pre-write-gate`)
  Everything else is post-hoc. `gate` runs in front of the edit — as a Claude Code
  PreToolUse hook on `Write|Edit`: "command": "unruster gate --hook" (no `jq`).

COMPARING RUNS (`unruster explain baseline`)
  Findings key on a line-number-free fingerprint, so an edit above one doesn't
  make it look new. `audit --since HEAD~1` reports gone/new/moved against a git
  ref (nothing stored — git is the baseline); `--write-baseline`/`--baseline`
  pin a CI snapshot, and `--fail-on-new` gates on regressions only.

WAIVERS — record a verified false positive (`unruster explain waivers`)
  // unruster: ok(<check>[/<key>]) <YYYY-MM-DD> — <reason>
  Never hand-written: `--suggest-waivers` prints the exact line. Above an item
  it waives that whole item (the `#[allow]` model). A bare enum name as the key
  covers all its variants; a group name (`partial-enumeration`) covers every
  check asking the same question. `unruster waivers [--orphaned]` audits them.

IN-SOURCE MARKERS (declarations live in `///`, waivers in `//`)
  /// unruster: sealed        on an enum: partial dispatch is tagged SEALED
  /// unruster: concept(x)    this item is the canonical home of concept `x`
                              (`unruster vocabulary` audits the claims)
  // unruster: ok(...) ...    waive a finding — see WAIVERS above
